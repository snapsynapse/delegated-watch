## [0.3.0] - 2026-10-03
### Added
- `npm run openai-compatible:capture`, one call-time capture for every OpenAI-compatible endpoint: presets for LM Studio, llama.cpp, vLLM, and MLX locally and for xAI, Mistral, DeepSeek, Groq, OpenRouter, and Together hosted, plus `--base-url` with `--source` for any other. The request and response pass through unchanged and only the model and counters are kept; the headline is prompt minus cached prompt plus completion, reading DeepSeek's cache field too. Streaming is refused rather than rewritten. Direct OpenAI calls remain excluded and its organization report is quarantined until a scope decision establishes whether it is additive.
- `npm run refresh`: one command from install to dashboard. It runs every extractor and estimator, imports, exports the CSVs, builds, and evaluates, reports each step as ok, unknown, or failed, and says where the dashboard is. The first run switches the checkout to a record of its own in a git-ignored `record/` directory, selected by a git-ignored `config/record.json`, so a person's record never enters a tracked or served path; every script resolves its data and output paths through `scripts/lib/record-paths.js`, and without that file works on the shipped demo exactly as before. Per-step arguments a person decides once live in `config/record.json` under `options`. In record mode the served-tree check always fails if the record's own values appear under `docs/`.
- `extract:vscode-agents` accepts `--token-convention SOURCE=value`, so one source's ambiguous records can be settled without guessing another's.
- `npm run extract:cursor`, reading each message's `tokenCount` from the `cursorDiskKV` table in Cursor's `state.vscdb`, through Node's built-in SQLite. Counts are recorded as Cursor reports them, because whether its input count includes cached context is not visible in the client; messages with no counts are skipped. Storage verified in Cursor 3.17.21 on macOS.
- `npm run extract:zed-agent`, reading Zed's agent threads from `threads/threads.db` in its data directory through Node's built-in SQLite and zstd. Each thread's cumulative usage counts once, dated by the day it was created so continuing it later never moves its total; the headline is input plus cache creation plus output, with cache reads kept in provenance. Field names verified in Zed 1.20.2 on macOS.
- `npm run extract:copilot-cli`, reading GitHub Copilot CLI session state under `$COPILOT_HOME` (default `~/.copilot`). Copilot writes per-call usage only in memory, so the durable record is each session's cumulative `session.shutdown` totals; each shutdown contributes its increase over the last, dated by the shutdown, and a total that falls starts fresh. The headline is input minus cache reads plus output. Verified against the @github/copilot 1.0.73 SDK bundled with VS Code; Copilot Chat inside VS Code keeps no token counts on disk.
- `npm run extract:gemini-cli`, reading Gemini CLI chat sessions under `$GEMINI_CLI_HOME/.gemini/tmp` (default the home directory) and Qwen Code sessions under `~/.qwen/tmp`, in both the JSON Lines and older single-JSON formats. Each model reply counts once from its latest tokens record; the headline is non-cached input plus output, thoughts, and tool-use prompt tokens, with cached input kept in provenance. Verified against Gemini CLI 0.58.0's own recording code.
- The TypeSafe capture, through the same hook and `npm run typesafe:capture`. A TypeSafe response has no request id or timestamp, so receipts key on a SHA-256 of the canonical response, and a retained response can be replayed with `--observed-at` to date it correctly.
- The Perplexity capture: `npm run install:perplexity-hook` registers a Claude Code PostToolUse hook that keeps the usage counters from every Bash tool result that reached the Perplexity API, and `npm run perplexity:capture` relays scripted requests. Receipts dedupe by Perplexity's own response id, keep the provider total where deep research bills beyond prompt and completion, and never record the query, answer, citations, or cost. The installer is Node, needs no shell or Python, backs up `settings.json` privately, preserves every other setting, refuses a file it cannot parse, and repoints rather than duplicates an existing entry.
- `npm run estimate:claude-chat` and `npm run estimate:chatgpt`, estimating consumer chat usage from account exports under `raw/` at four characters per token. The claude.ai estimate counts thinking, tool calls, tool results, and attachment text, keeps Claude Design separate, and dedupes overlapping exports by message; the ChatGPT estimate reads ZIPs, manifests, and sharded conversation files, refuses a manifest that points outside its export, and records each day's own models. Receipts are schema v2 with estimated authority; an unreadable export exits 3 and leaves the previous receipts untouched.
- `npm run extract:claude-api` and `npm run extract:openai-api`, reading the Anthropic Admin Usage Report and the OpenAI organization Usage API with an admin key from the environment. Receipts are schema v2 with provider authority, and cache reads or cached input are excluded from the headline. Without a key each exits 0 having asked nothing; an unreachable provider exits 3 and an HTTP error exits 1, and neither logs the key or a query string. Both organization reports stay quarantined until a human reconciliation decision establishes that they are additive. Anthropic currently keeps cache evidence in provenance and has one global reconciliation mode. OpenAI preserves reported token components, binds each decision and display alias to one unique stable non-secret organization scope, uses a full SHA-256 scope fingerprint in persisted identities, preserves zero-headline activity, and writes separate receipt files for separate organizations.
- `npm run extract:vscode-agents`, reading the task stores of Cline and the extensions built on it, Roo Code, Kilo Code, and Snapdev, in VS Code, VS Code Insiders, VSCodium, Cursor, and Windsurf. It reads only the settled request counters, decides the cache-counting convention per record, and refuses records the counters cannot decide unless `--token-convention` breaks the tie. Each source is written or held back independently. The dashboard labels `cline` and `roo_code`.
- `npm run extract:goose`, reading goose's `usage_ledger` through Node's built-in SQLite in read-only mode, so no `sqlite3` program is required and committed WAL frames are included. The database follows `GOOSE_PATH_ROOT`, the Windows application-data location, or `XDG_DATA_HOME`. Local models map to their family source id and hosted providers to `goose_<provider>`. Rows with cache reads need `--cache-convention` and are otherwise reported as undecided with exit 3; a database without a usage ledger or that is not SQLite is unknown, not empty. The ledger's cost column is never read.
- `npm run extract:codex`, reading Codex rollouts under `$CODEX_HOME` (or `~/.codex`), sessions and archive both, read-only. It counts non-cached input plus output, dedupes repeated cumulative snapshots, notes counter resets, and keeps cached input in provenance. A custom `--sessions` root must declare `--local-store` or `--tag`, so a copied store never inherits this machine's identity. Stores are reported and classified like the Claude Code extractor's.
- `npm run extract:claude-code`, the first ported extractor. It reads Claude Code transcripts (`$CLAUDE_CONFIG_DIR/projects`, or `~/.claude/projects`) and the Claude desktop app's agent session stores read-only, dedupes streamed rewrites by request id, excludes cache reads from the headline while keeping them in provenance, and writes schema v2 receipts, one file per source. Each store is reported as read, not found, or unreadable; unreadable exits 3 and leaves that source's previous receipts untouched. `--source`, `--root`, `--tag`, and `--since` select stores, recover from backups, and attribute other machines.
- `SURFACES.md` opens with a supported-services list: what ships, what has a tested extractor being ported, what is not yet supported, and what is never countable. `INTENT.md` gains "Who it is for", and `ROADMAP.md` puts porting the tested extractors first.
- `eval:served` checks every sitemap entry against the page it names: the served file exists, its canonical is the sitemap URL, it is not noindex, its JSON-LD parses, and every modified date it states equals the sitemap `lastmod`, which must be a valid date not in the future. It also checks that `404.html` is noindex and absent from the sitemap.
### Changed
- Receipt schema v2, accepted evidence, the dataset, validation, dashboard model, and detail CSV now preserve optional input, output, cached-input, cache-write, and reasoning token components. Missing components remain unavailable and explicit zeroes remain measured zero.
- Provider-to-tool authority replacement now converges across fresh and persisted imports for one complete request set. Partial, cross-day, cross-account, and equal-authority cross-source conflicts still fail closed, and superseded receipt identities remain as non-additive history.
- OpenAI organization usage is attributed with minute-precision timezone boundaries for fractional offsets, while daily UTC and whole-hour buckets retain their documented semantics.
- `SURFACES.md` separates four verification levels, Real data, Parity, Tool's own code, and Synthetic, and states that only the first means this release has counted real usage. The Anthropic, OpenAI, Perplexity, and TypeSafe rows move from Real data to Parity, which is what was actually checked, and Ollama to Synthetic. `ROADMAP.md` records the plan: install, use, and test each tool before its row can claim Real data.
- `SURFACES.md` keeps one list of every agentic surface, grouped by kind: what ships, with whether it was verified against real data, the tool's own code, or synthetic fixtures; what is planned and by which method; what is still being researched; and what can never be counted. `ROADMAP.md` lists the planned surfaces in build order.
- `docs/sitemap.xml` is built by `npm run build:landing` from `config/site.json`, rather than kept by hand. Its `lastmod` is the same `landing.date_modified` the home page states as `article:modified_time` and JSON-LD `dateModified`, so the three cannot drift apart. The built file is byte-identical to the one it replaces.
- The CI reproducibility check hashes `docs/sitemap.xml` alongside both pages, so a committed sitemap that a build would change fails the job.
- `eval:code` scans `src/` as well as `scripts/`, because dashboard source is baked into the served page. The inline-personal-constant rule flags any IANA timezone literal rather than one named zone.
### Fixed
- Copied Codex forks no longer count their inherited token events a second time when explicit `forked_from_id` lineage and the complete structural prefix agree. Referenced forks and unrelated equal-count events remain distinct; missing or ambiguous lineage retains the evidence and marks its coverage incomplete through receipts, imports, validation, and the dashboard.
- Codex extraction now fails closed on malformed interior JSONL and incomplete final appends, preserving prior output instead of publishing a partial exact count. A rerun after the final record becomes complete accepts the full evidence.
- Zero-token entries now require positive call evidence or positive measured token-component evidence. This preserves provider-reported activity without admitting empty placeholder rows that would turn unknown into zero.
- OpenAI legacy-output migration now requires readable, unambiguous evidence that the current scoped extraction equals or dominates in tokens, calls, and every retained component. Unreadable, malformed, partial, or regressing legacy evidence is retained and blocks a competing scoped output.
- OpenAI organization bindings now reject one organization scope under multiple display aliases. Additive legacy migration preserves a recovery copy and removes the legacy file from importer reach before publishing the scoped file; a publication failure restores the legacy input instead of leaving both identities importable.
- A first run keeps a person's whole history. `window_start` in `config/profile.json` defaults to 2022-11-30, ChatGPT's public launch, instead of the synthetic demo's year, which made the importer refuse any older receipt and the ChatGPT and OpenAI extractors stop reading at 2025. The demo frames its own year through a synthetic-only `window_start` in `config/site.json`.
- The landing byline no longer shows a gap before its comma: each phrase is one element, so the flex gap separates phrases rather than punctuation.
- On a phone the landing navigation keeps its section links on a row under the logo, with the GitHub star reduced to its icon, instead of hiding every link but the star.
- The demo is anchored to `as_of` in `config/site.json`, which the renderer inlines only for a synthetic dataset and the banner states. Its recent windows, freshness ages, and 1y range now describe the synthetic year instead of the months since it ended. The synthetic generator makes the final fourteen days active so the seven-day average shows a value; earlier rows are unchanged.
- The GitHub tile is withheld when no GitHub summary is configured, instead of reporting a lookup that never ran.
- A filter combination with no matching evidence reads "No match" in the headline instead of "0 tokens", which read as a measured zero.
- `npm ci` works from a fresh clone. The landing page and the assistant guide both run it, and it refused with EUSAGE because no lockfile existed. `package-lock.json` records the empty dependency set and is inventoried. The separate v0.3.0 guide rotation is recorded in Changed above.
- The `--fresh-history` test disables commit signing for its fixture commits, so the suite passes for a contributor with `commit.gpgsign` set and a locked key.
- The dashboard's legacy-row fallback reads the timezone from the profile instead of a hard-coded zone.
- Code comments, an error-message example, a test fixture, and a configuration note no longer carry details of the author's own record: a former timezone, a real token figure, the earliest recovered day, a local account name, or the name of the private producer repository.

## [0.2.1] - 2026-09-22
### Added
- An "Adjacent tools and what this is not" section in `INTENT.md`, mapping the five nearby categories (provider billing dashboards, LLM observability platforms, coding-agent analytics, agent-operation dashboards, FinOps tools) and why none is what this repository does. ### Changed

A language model's tokens, not cryptocurrency: no blockchain, no supply, no burning in that sense, and nothing denominated in any currency. A research tool misread the project this way, which makes it a documentation defect rather than a reader's error. `llms.txt` says it first, before anything else a machine reads, and also disambiguates from `delegated.to`.
- Page keywords name LLM tokens explicitly and drop the bare "token burn" phrasing, which is retained only where it cites the originating post.
- `README.md` gives the clone command rather than only saying to clone, and gains a Contributing section pointing at `CONTRIBUTING.md` and `SECURITY.md`.

## [0.2.0] - 2026-09-22
### Added
- A footer of routes off the page, driven by `config/site.json`: source, data contract, privacy, issues, and `llms.txt`. A build without a site config renders none.
- Social card art at `imgs/og.png` and `docs/imgs/og.png`, referenced from the page's OpenGraph, Twitter, and structured-data metadata.
- Issue and pull request templates under `.github/`.
- A home page at `/` describing the project: the three invariants, how receipts become a dataset, what the record cannot see, and what it is not. Built from `src/landing.html` by `scripts/build-landing.js`, with `TechArticle`, `SoftwareApplication`, and `WebSite` structured data, a byline with published and updated dates, IndieWeb `rel="me"` links, a skip link, and a canonical-reference note.
- `demo_path` in `config/site.json`, naming the public route of the built dashboard, and a `landing` block carrying the byline, dates, version, and the landing-only footer routes.
- `npm run build:landing` and `npm run build:demo` build one page each; `npm run build` builds both.
- An assistant guide at `/.well-known/assistant-guide.txt`, conforming to the GuideCheck Human-Verifiable Assistant Guide profile 2.0.0 at Level 4. It is the agent-facing install path: explicit scope and non-goals, a compact verification instruction before any action, and one structured action block per step with an approval gate on every networked and code-executing command. The hosted verifier reports Level 4 on 2026-09-22 with one qualifying anchor and zero blocking findings. Level 4 is the highest level a guide file can reach; Level 5 belongs to a conformant assistant runtime, not to a file.
- A sidecar manifest at `/.well-known/assistant-guide-manifest.txt` pinning the guide's SHA-256 and byte count, named from the guide's `manifest-url`, with the same hash cross-published as a DNS TXT record at `_assistant-guide.delegated.watch`. Those three land together by necessity: a guide declaring `manifest-url` is evaluated against Level 4, so publishing the manifest ahead of its anchor would make a fetching verifier report a missing anchor as blocking and tell every assistant not to proceed. Verifiers do not fetch the manifest's `immutable-release-url`, so the forward reference to an uncut release does not hold the level back; the profile permits a manifest to name the release that will contain the guide.
- The `config/known-activity.json` schema is specified in `DATA_CONTRACT.md`. The file, its build path, its rendering in the dashboard's freshness panel, and three checks in `npm run eval:dashboard` all shipped in 0.1.0; the schema appeared in no documentation, so a working feature was undiscoverable. A person can record a bound by hand today. The three rules are restated there: a bound is not coverage, is never summed, and never reaches a token figure.
- `ROADMAP.md`, in priority order, led by the gap between invariant 5 and receipt schema v2: the invariant says cache and reasoning tokens are preserved in receipt provenance and the schema has no field to preserve them in. Then dates-only capture for quota-reporting surfaces, which is the only item that adds a class of evidence the record has never carried rather than improving figures it already has. Then `route` as a dimension independent of provider and surface, a `model_requested`/`model_resolved` split, gateway extractors as a source class rather than as an architecture, and local inference beyond Ollama. It also records what is permanently decided against, so cost fields, prompt hashes, transcript pointers, organization and team fields, event-level storage, and a gateway backend are not re-proposed.
- A Reported status in `SURFACES.md`, between Documented and Recognized, for a surface whose behaviour is claimed by secondary research and unconfirmed against the product. Reported rows carry a date, because vendor reporting changes without announcing itself. Consumer chat products move to Dates only as the working assumption, which inverts the burden of proof for that row group: an exact token figure from a consumer subscription is now the claim requiring evidence.
- A second axis in `SURFACES.md` recording where a counter comes from, not only whether one can exist. A provider response, a cloud billing export, a gateway record, and a client-side reconstruction can all be exact and are not equally authoritative.
- `SURFACES.md`, the authoritative register of every surface and what can be recovered from it. It distinguishes four recovery states rather than two: exact, estimated, dates only, and unrecoverable. Every source id the dashboard labels has a row, and a row the repository cannot justify is marked Recognized, meaning unassessed, rather than implied to work.
- A questions section on the home page covering what the record can read, what is permanently out of reach, how much this release actually ships, whether anything leaves the machine, how far back it goes, why tokens and not money, publishing, and adding a surface. Each answer points at the file that governs it.
- `tests/assistant-guide.test.js` asserts the guide's byte profile, size limits, unique action ids, approval gates, declared egress, every `exec-sha256` pin against the script it names, and the manifest's hash and byte count against the guide's actual bytes. A pinned script or a drifted manifest fails the build, because a stale pin reads as provenance while binding bytes that no longer exist.
- The home page links the published real record at sam-rogers.com/ai-usage as the worked example beside the synthetic demo, and names the GuideCheck level it claims.

### Changed
- The home page states where the burden of proof sits: an exact token figure from a consumer subscription is the claim requiring evidence, not the default. The answer on what this release ships now describes the register's evidence grades rather than only its unassessed rows, and the footer links the roadmap.
- The home page now leads with the claim the project actually makes: one record across every provider, every interaction surface, and every machine, for as far back as the evidence survives, rather than one vendor's dashboard for the last thirty days. Adds a scope section arguing it, an install section with an agent path and a human path, and drops the generic flow diagram.
- The dashboard moved from `/` to `/demo/`. It is the demonstration of the project, not the project's home page, and it now says so: away from the site root it carries `WebPage` structured data inside the site rather than `WebSite` and `SoftwareApplication` claiming to be the site, and its title, canonical URL, and social metadata name the demo.
- The dev server serves both routes, derived from `config/site.json` rather than hardcoded, so a local path matches the served one. A config without `demo_path` keeps the historical behaviour, where the dashboard is the only page and answers at `/`.
- The CI build-reproducibility step hashes both built pages, not only `docs/index.html`.
- CI moves to Depot CI, which executes `.depot/workflows/ci.yml` directly. The GitHub Actions copy at `.github/workflows/ci.yml` is retained as a `workflow_dispatch` fallback and no longer runs on push or pull request. Both copies drop the `macos-latest` matrix leg and verify on Linux across both Node versions, and both accept `workflow_dispatch` so a run can be fired by hand.
- The CI workflow tests now assert against both copies rather than the GitHub one alone, and fail if their steps lists drift apart, if they diverge anywhere beyond their triggers and matrix legs, or if anything appears under `.depot/` besides the workflow itself.
- CI runs every eval under `--strict`, so a WARN now fails the build instead of passing unread, and a test asserts the flag stays on each eval step in both workflow copies.
- The served-tree eval checks that every real link in the served HTML resolves to a served file or an existing fragment, that own-domain URLs are all `https` and bare, and that the sitemap lists only canonical-origin URLs. `data-href`, which the page activates at runtime, is deliberately not treated as a link.

### Fixed
- The home page's two code blocks scroll horizontally below roughly 700px and were neither focusable nor named, so a keyboard-only reader could not reach or scroll them and a screen reader announced no region. Found by measuring the live page at 360px in a real browser. Three axe runs had reported the page clean and none could have caught it: the scanner fixes its viewport at 1280x800, where the blocks do not scroll and the condition does not exist. They now carry `tabindex="0"`, `role="region"`, an accessible name, and a focus ring of their own, and `tests/ui-accessibility-contract.test.js` asserts all four on every CI job.
- The publication CTAs shipped `href="#"` while hidden, which a raw-HTML fetcher reads as a link to nowhere; an external agent-readiness scan counted both as dead CTAs on the live site. The attribute is now absent until activation supplies a real URL, matching how the records link already worked.
- The burn drivers list scrolls on its own but was not keyboard reachable, and the time-range panel carried an `aria-label` with no role. Found by a live axe-core scan on 2026-09-22; both are now asserted by the accessibility contract test.
- Social card art carried EXIF and text metadata chunks, which the candidate verifier rejects for any published image.
- The CI build-reproducibility step compared one fresh build against another, so both sides were freshly built and always agreed while a committed page could stay a build behind. It now compares the committed bytes against a build first, then builds a second time for reproducibility. A config change consumed by only one of the two pages is the drift this missed.
- `verify:candidate --self` reported every git-ignored working-tree path as a file outside the inventory. A path git ignores and does not track cannot reach a published candidate, so it is now excluded from the walk and the count of excluded paths is reported; a tracked file stays in scope even where an ignore rule would match it.

## [0.1.0] - 2026-09-22
### Added
- First public release of the candidate tree: receipt schema v2, a deterministic importer with cutoff, no-decrease, settled-entry, exclusion, and reconciliation gates, and a single normalized dataset file.
- Static dashboard build and a loopback-only local dev server that serve the same self-contained page.
- CSV export, an evidence manifest and validator, and a read-only privacy scan over retained receipts and labels.
- The Anthropic API reconciliation oracle for comparing provider-reported usage against transcript-derived usage.
- One reference capture, for local inference through Ollama, that persists only model identity and authoritative counters.
- A synthetic demonstration dataset and fixture receipts, plus tooling to assemble and verify this candidate tree against its own inventory.
### Not included
- Provider-specific extractors for hosted chat products, IDE extensions, or organization usage APIs.
- The scheduled automation that runs a private pipeline unattended.
- Any real usage data. Every row shipped in this release is synthetic.
